SPINDOCTOR 3.1.0 PRESET EXECUTION UPDATE
Direct built-in circuit presets now create and run 1,024 shots by default.
Examples: q.circuit preset bell; q.circuit preset qft 5 shots 2048 basis x.
Explicit shots and basis override defaults; run=false defines without running.
The existing maximum of 100,000 is retained. Catalog sampling presets default
to1,024; a collapsing measurement still requires one shot. Deterministic
mathematical calculations and resource estimates do not execute shots.
Earlier guide/source descriptions below describe the original source record;
the current native registry and actual queued/completed returns are authoritative.

HOW TO USE THIS FILE
This is the installed preset library plus historical design labels. Use q.preset list and q.help for runtime availability. Unsupported qc-198 remains visible with a specific explanation. Proposed labels below describe the original design and do not disable installed implementations.
Use SPINDOCTOR_PRESETS.json for machine-readable menu records, SPINDOCTOR_BUILD_BRIEF.txt for the implementation handoff, and SPINDOCTOR_QUANTUM_GUIDE.txt for formulas and article corrections.
A preset is a sequence of ordinary commands. The UI runner must await asynchronous completion between dependent commands; a status command alone does not wait. If entering commands manually, check status until the job completes before continuing.
Fresh-circuit presets may select a new active circuit. Use unique names or clone on collisions; preserve user circuits/checkpoints. Read prerequisites before commands that prepare or modify state.
q0 is the least-significant bit; display |q(n-1)...q0>. Angles in existing commands are numeric radians. Exact predicted probabilities and fluctuating shot counts are separate.
The 500-trillion address family contains independent single-qubit states. Only the selected joint tranche/circuit is calculated for an entangling command. Dense 29-qubit complex128 states need 8 GiB before work buffers; the documented default cap is 512 MiB.
Menu filtering should distinguish observed syntax, proposed extension, independent-state versus joint-register scope, backend prerequisites, and numerical/approximate/theory results.
Downloadable TXT returns should identify nonmeasurement commands and retain scope, seeds/counters, actual work, timing and completion state.

PROPOSED GRAMMAR CONTRACT
options: Each proposed extension command uses family action followed by key=value arguments. Quote expressions containing spaces. Square brackets represent typed lists or matrices; parse their contents rather than executing them as host-language code. A quoted gates="...;..." or left="...;..." value is one safely parsed gate-sequence field; its semicolons are not terminal macro separators or shell separators.
complexNumbers: Accept numeric decimals, rational constants, i, sqrt(...), exp(i*theta), and pi through a restricted mathematical expression parser. Reject unsafe names, code evaluation and nonfinite values.
qMath: q.math accepts supplied vectors, matrices or gate names. Return exact algebra when independently verified; otherwise label numerical approximations and state tolerances.
qQuery: q.query reads the selected circuit's completed premeasurement state. Enforce output bounds. Pauli strings use explicit labels such as X0 X1. A requested qubit-list order must be shown in the output.
qNoise: q.noise accepts explicit states/circuits and channel conventions. Build physical density matrices using Kraus maps or equivalent verified formulas. No unitary-only backend may claim to produce mixed-state evolution.
qQec: q.qec performs ideal code demonstrations with explicit generators, error sets and recovery assumptions. Educational code models do not imply hardware fault tolerance.
qCompile: q.compile checks identities, classifications and metrics under specified conventions. Numerical synthesis requires a real algorithm and independent matrix-error verification.
qResource: q.resource performs explicit arithmetic under declared dtype, representation, cap and overhead assumptions. No estimates imply successful allocations or hardware capacity.
qModel: q.model requires explicit Hamiltonian and energy conventions. Universal model equivalence is separate from specific hardware claims.
qLesson: q.lesson returns explanations. Browse primary sources for current standards, device claims or contested claims; mark conjectures and assumptions.
qAlgorithm: q.algorithm expands a declared small algorithm into explicit gates and initial states before simulation; declare oracle, eigenstate, controlled-power mapping, swaps and bit order. Report ideal probabilities separately from samples.
